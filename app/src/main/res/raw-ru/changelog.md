# DSHA 0.2.1-rc.5-20261111.1200-dsh0.2.2-rc.1 / build359

- Надёжность остановки / перезапуска (T154, `5b517e7ff` + правка шлюза `5e4509d2b`): при обычной остановке, если процесс жив после льготного окна SIGTERM (6,5 с) и его командная строка всё ещё является управляемым proroot bridge этой установки, хост дважды проверяет «та же идентичность рождения + proroot bridge / лаунчер этой установки» и только затем контролируемо повышает сигнал до SIGQUIT; если через 1,5 с он ещё жив, проверка повторяется дважды и сигнал повышается до SIGKILL с подтверждением выхода в течение 2 с. Любое несовпадение идентичности / записи PID / сигнала сохраняет сцену, а в квитанции указывается уровень сигнала. Резерв доказательств принудительной остановки: сканирование остановки сохраняет остаточные факты, в которых совпали две проверки ядра, поэтому кандидат можно подготовить даже при отсутствующем, устаревшем или уже снятом файле PID / идентичности; перед отправкой сигнала хост повторно проверяет дважды и отказывает при несовпадении. Если остановка перед запуском не удалась, страница запуска сразу предлагает пункт «Принудительно завершить» (перезапускать приложение, как в сцене 09:13, не нужно). Допуск принудительной остановки теперь использует явный белый список выводов о неподтверждённой остановке, и после здорового запуска пункт должен быть закрыт. Красные линии неизменны: сигналы только PID с проверенной идентичностью, не по имени / порту / голому PID, UNKNOWN не повторяется.
- Наблюдаемость частичного рендеринга Web (T153, `81d253428`): ошибки загрузки подресурсов не главного фрейма записываются как `WEB_SUBRESOURCE` (query / fragment удаляются, белый список путей, ограничение на страницу); после завершения страницы и изменений маршрута SPA хост сэмплирует зонд `[DSHA_ROUTE]` и записывает `WEB_ROUTE_BLANK` только при устойчиво пустой странице, показывая нативную карточку-запасной вариант (перезагрузить / повторить в безопасном режиме / скопировать сводку диагностики); необработанные исключения попадают в `WEB_JS` через console.error (300 символов на запись, не более 20 на страницу, одинаковые сообщения дедуплицируются 5 с).
- Диагностируемая деградация обслуживания / аварийного экспорта (T153): перед обслуживанием выполняется ограниченная оценка места (насыщающее сложение, без переполнения); прогресс capture показывает число файлов / байт и предупреждает после 2 минут без прогресса; сбои классифицируются по месту / нечитаемому root / изменению источника / foreground-сервису / лимиту записей и указывают логическое имя root. Аварийный экспорт сразу возвращает типизированную причину и следующий шаг, при сбое записи SAF переходит к скачиванию через MediaStore, а пакет экспорта содержит ограниченно принимаемый `diagnostics.txt` (старые версии отклоняют этот дополнительный элемент).
