# DSHA-god · 新生计划

### 代号：嫩芽 · Sprout 🌱

**以容器为底座，生长为可组合、可定制、可扩展的 Android 工作台。**

DSHA-god 是「新生计划」的工作与构建仓库。我们希望把 Android 宿主能力、容器中的 AI 工作环境，以及可组合的功能模块连接起来，而不是只重新打包已有应用。

> **当前阶段：筹建与基线接入准备。**
> 仓库介绍与发展方向正在建立；新主线源码、构建流水线与验收闭环仍在接入中。本文中的路线是规划，不表示功能已完成或已经过真机验证。

## 我们要做什么

- **容器底座**：集中容器运行路线，保留 Android 壳、设备桥、终端、虚拟屏与独立应急能力。
- **模块优先**：先明确宿主、模块与 AI 运行时的边界，再用一个低风险内置模块验证完整闭环。
- **能力分域**：Root、存储与网络等能力通过受控接口协作，权限申请、执行、撤销和恢复各有明确职责。
- **体验可验证**：高刷、长会话体验与浏览器兼容以测量和回归为依据，不以配置项或构建成功代替体验验收。
- **数据与控制权**：保留已有数据和可恢复路径；敏感操作需要相应授权，用户能够暂停、接管和撤销。

## 路线图

| 阶段 | 目标 |
|---|---|
| 1. 地基 | 接入精确来源基线，建立可重复的构建、测试与包校验流程 |
| 2. 契约 | 明确最小模块协议，完成一个内置低风险模块闭环 |
| 3. 体验 | 验证高刷与性能，建设默认 WebView、可选 Gecko 的一体方案 |
| 4. 能力 | 分批接入受控 Root 模块管理与故障恢复 |
| 5. 生长 | 在协议与宿主稳定后，再推进桌宠、对话窗口、角色及交互扩展 |

当前不承诺上述规划已经实现，也不把桌宠原型作为地基工作的替代品。

## 当前边界

原 Android 原生 DSH 运行时路线停止投入；这不代表取消 Android 原生宿主、设备能力或应急工具。

模块化不等于安全沙箱，同 UID 或容器环境也不自动提供恶意代码隔离。具体能力支持、兼容矩阵和安全限制，以后续实现及验证结果为准。
