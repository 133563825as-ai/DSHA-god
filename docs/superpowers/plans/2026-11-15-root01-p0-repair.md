# Root-01 P0 Repair Implementation Plan

> **For agentic workers:** Implement in this session. Keep PR #4 Draft until both safety invariants and device evidence pass.

**Goal:** Make Root revocation durable across process death and close the claim-to-write handover gap without an unbounded UI stall.

**Architecture:** Root remains disabled on every new app process until an explicit, durably saved user enable action. The effective policy starts Strict on every process, so stale permissive disk values cannot silently recover. The App stages a framed request while the helper waits without executing it. After the helper acknowledges the matching nonce, the App sends a one-byte commit and EOF under the same gate used by revocation. Revocation can finish while staging blocks; a staged request without commit is inert.

**Tech Stack:** Java 17, Android SharedPreferences, JUnit/Robolectric, Gradle, Xiaomi 17 Pro Max.

**Spec:** `docs/root-security-root01-delivery.md` and user-supplied Root-01 acceptance requirements.

## Global Constraints

- No destructive Root commands or private device data.

## Review Focus

- Stale persisted `true` after process death must not auto-authorize.
- Stale persisted Full after process death must be effectively Strict.
- Failed `commit()` must not arm Root or claim saved revocation.
- Revocation racing with blocked handover must have a bounded, truthful completion state.
- Partial request or EOF failure must remain UNKNOWN, with no automatic retry.
