## 本次行为

- 新 App 进程始终 Root 关闭、有效策略 Strict。磁盘旧 `true` / Full 不能自动恢复权限；用户必须在本进程明确开启。
- Root 开关和档位使用后台 `commit()`，只有持久保存成功且设置代次仍有效才发布授权。失败保持关闭，迟到保存不能复活旧代次；慢磁盘不持有交付锁。
- App 先写长度帧和完整请求；helper 解析后只返回随机 nonce 暂存回执，不执行业务。App 收到匹配回执后，在 Root gate 内复查权限、发送一字节确认并关闭 stdin；helper 只有收到确认及 EOF 才能继续。
- App Root 撤销与最后确认/EOF 共用 gate。预写或等待回执期间可以完成撤销，旧请求关闭流但不发送确认；已越过确认边界的请求按已派发处理，未知结果不重放。
- guest `/device/plan?su=1` 使用同一个有效会话授权；外接三类请求在 helper 暂存之后再检查业务授权。
- UI 保存期间禁用 Root 开关，标题不能绕过禁用；回调及恢复页面时同步有效授权。保存提示登记十种语言，语言字节摘要随新增译文更新，未关闭摘要校验。

此协议只界定 App Root 开关的交付边界。helper 暂存回执证明请求已被读取，不证明业务已执行。最终确认失败、结果损坏、超时或中断仍必须报告 UNKNOWN，不自动重试。
