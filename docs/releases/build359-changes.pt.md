- Fiabilidade de paragem / reinício (T154, `5b517e7ff` + correção de portão `5e4509d2b`): numa paragem normal, se o processo continuar vivo após a janela de tolerância do SIGTERM (6,5 s) e a linha de comando ainda for a bridge proroot gerida desta instalação, o anfitrião faz uma dupla verificação («mesma identidade de nascimento + bridge / launcher proroot desta instalação») e só então escala de forma controlada para SIGQUIT; se ainda estiver vivo 1,5 s depois, volta a verificar duas vezes e escala para SIGKILL, confirmando a saída em 2 s. Qualquer divergência de identidade / registo de PID / sinal mantém o cenário intacto, e o recibo indica o nível do sinal. Recurso de prova de paragem forçada: a varredura de paragem guarda factos residuais em que duas verificações do kernel concordam, pelo que é possível preparar um candidato mesmo com o ficheiro de PID / identidade ausente, obsoleto ou já retirado; o anfitrião volta a verificar duas vezes antes de enviar o sinal e recusa em caso de divergência. Se a paragem pré-arranque falhar, a página de arranque oferece diretamente uma entrada «Forçar paragem» (sem reiniciar a aplicação como no cenário das 09:13). A admissão da paragem forçada passa a usar uma lista explícita de conclusões de paragem não confirmadas, e a entrada tem de ficar fechada após um arranque saudável. Linhas vermelhas inalteradas: os sinais só vão para PIDs com identidade verificada, nunca por nome / porta / PID nu, e UNKNOWN não é repetido.
