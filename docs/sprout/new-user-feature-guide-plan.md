# 新人功能引导方案 v0.2

> 状态：仅方案，未实现／未真机验证。用户已选择“先方案，首包后实现”；随后确认由桌宠模块角色形象配合气泡进行引导，形象修订另议。不加入当前overlay修复批次。
> 日期：2026-11-12｜导航核对基线：共同源码`4027e4c8a84fa25b09d9b3d7e6b8f833b898dd1e`。实现前以当时集成树再核，不承诺路径永久不变。

## 1. 要解决什么

新人常能进入DSH工作台，却不知道Android宿主还提供终端、插件、设备能力、备份和应急恢复。目标是回答三句话：**能做什么、在哪里、什么时候用**，而不是再让新人读一遍架构或完成第二套授权向导。

第一版成功标准：新人能找到原生功能入口，知道回到功能说明的方法，并明确“返回／隐藏页面不等于停止任务”“看过介绍不等于授权”。不以点完页数、打开权限或运行命令当成学会。

不包含：重做安装部署、改维护门禁、强制登录、模块市场、自动命令演示、真实手机控制、自动备份／恢复。Gecko、Root模块管理和桌宠尚未实现的能力不能提前写成可用按钮。

## 1.1 用户确认的交互方向（取代v0.1默认卡片式主引导）

- **主引导由桌宠模块的角色形象承担**，配合小气泡、轻任务式逐步介绍，类似小游戏中的新手伙伴；不另造一套无关角色。六张功能卡保留为可查阅的帮助总览，不再视为最终主引导交互。
- 形象当前存在待修改问题，用户要求后续再议。本次不确定造型／素材／动作，不修改桌宠资产、不做HTML或UI原型，也不提前宣称桌宠模块已完成。
- 工作台回原生功能的入口将另行改进为直接可达；具体宿主导航与生命周期方案实施前再核。本方案不编造当前已有通路，不把返回键固定行为写死。
- 复用的是角色与展现能力，不把guide阅读状态／步骤强绑到桌宠业务或系统悬浮权限。桌宠未安装、停用、资源不可用或用户不愿开启时，仍可访问离线文字指南；不为学习功能而强迫开启常驻悬浮窗。应用内讲解与桌面悬浮形态的具体承载后续评审。
- 气泡可跳过、暂停、重看，不遮挡原生确认／敏感界面或正在执行的手机操作；指向实际可用入口，导航之后先确认界面再介绍，不自动点按或执行业务。完成提示不以授权、登录、付费、备份写入或命令执行为条件。
- 排期仍为首包门禁收口后，届时先讨论形象改进及桌宠接口，再细化锚点、跨原生／Web跟随与失败回退。当前只记录方向，不扩大实施范围。

## 2. 和现有首次引导的关系

既有[首次部署引导设计](../design/onboarding-20261031/README.md)负责欢迎→用途→授权→完成；该历史设计还含与现行维护门禁不同的旧提案，不能照搬整个流程。

新功能引导在**安装／维护门禁已放行、当前原生界面稳定且没有待确认操作**时才允许显示一次轻量邀请：

> **不止是聊天工作台**  
> 了解终端、插件、设备能力，以及出问题时如何保住数据。可以随时跳过，稍后在“功能指南”里再看。

按钮：“了解功能”“以后再看”。不倒计时、不自动跳页、不拦进入工作台。升级旧用户只出现一次邀请，不重置已有首次安装／授权记录；不在每次启动、每次CI版本号变化时重弹。

## 3. 可发现的常驻入口（新增提案）

- 原生主界面：顶栏“+”内新增“功能指南”，手机和平板同一路由。
- 设置：新增“帮助与功能指南”或等价稳定入口，不强塞到“关于”底部。
- **正在工作台里的用户也必须能找回原生功能**：在现有宿主所有的工作台菜单中提供“DSHA功能指南／原生功能”入口，再由宿主导航；不能只把说明放在用户已经找不到的原生页。

最后一项的真实Web→原生通路需要实现前单独核对，不能在方案里编一个未存在的deep link。现有Web返回可能先消费网页历史，直启Web模式下还可能回桌面；**不要教新人“按一次返回就一定回到原生首页”**。若没有可靠既有通路，作为引导实现的必要小型导航项单独审查，不插入任意网页JS／全局快捷键替代。

常驻入口应离线可读。长版说明可引用现有仓库文档，但第一屏及每项三句话必须随包提供，不依赖GitHub、账号或模型在线。

## 4. 内容结构：总览＋六张卡，按需阅读

这六张卡现作为桌宠气泡引导的内容目录及随时可查的帮助总览，不强制走6步。每卡只含一个用途、真实路径、风险提示和“查看入口”导航；“查看入口”只导航，不默认执行业务。气泡编排及角色表现尚待后续设计，先覆盖工作台与终端，再介绍进阶能力。

| 卡片 | 建议短文案 | 已核现有入口／实现事实 | 禁止误导 |
|---|---|---|---|
| 工作台：对话与任务 | “描述目标，让助手在当前工作区处理文件和任务。重要操作先核对提示和结果。” | 原生启动页启动／进入→WebPreviewActivity；进入是否可用由真实就绪状态判定 | 进入工作台不等于所有功能已授权；隐藏／返回不表示任务停止 |
| 本机终端 | “需要手动查看环境或运行命令时用。第一次先了解当前会话和目录，不必照抄陌生命令。” | 原生底栏／宽屏左栏“终端”是打开TerminalActivity的导航动作，不切换根页 | 点指南／终端入口不创建命令、不执行粘贴内容；不暗示终端天然Root |
| 插件 | “插件为工作台增加能力。先看来源、启用状态和风险，不需要一次装齐。” | 原生“插件”页；环境未就绪时按原门禁转恢复说明 | 列表存在不等于已激活；不推荐绕版本／来源保护或默认开启所有插件 |
| 设备能力 | “让助手读屏、操作应用等，需要你明确提出任务，并按需授权。” | 设置→设备能力授权（DeviceGrantsFragment）；工具按实体／虚拟屏模式与能力条件分流 | 介绍不申请无障碍／悬浮窗／Root，不启动手机任务、不要求全部开；无障碍、截屏、通道和确认是不同门槛 |
| 数据与备份 | “重要数据先备份，升级或恢复前先看范围与目标。恢复不是撤销一切的按钮。” | 设置→数据与备份（WorkspaceFragment）；使用现有备份／恢复流程 | 只导航，不创建／覆盖备份，不调用恢复，不清数据；加密口令丢失不能承诺可找回 |
| 出错时：日志与应急 | “先看状态与脱敏诊断，再考虑维护或独立应急；保留现场，不反复重置。” | 启动日志、顶栏“+”的运行环境入口、现有维护／启动恢复页中的应急出口 | 查看指南不启动维护／应急进程、不强停；复制日志前提醒可能含本机地址和敏感信息，只分享给可信对象 |

另设可展开“更多功能”：下载记录、局域网访问、任务状态显示、语言等。只链接当前真实入口；局域网条目必须写明可信网络和链接保密，不从指南自动开启监听。

## 5. 交互与状态

- 第一次邀请“以后再看”持久化，不等于完成引导；常驻入口始终可用。再次进入默认总览，可手动续看上次卡片。
- 建议独立字段`featureGuideSchemaVersion / offeredVersion / dismissedVersion / completedVersion / lastCardId`；这些是设计候选，不是当前ConfigStore已有键。阅读偏好与业务授权、`welcomed`、备份格式、运行时身份分开。具体存储位置与是否进入便携设置，实施时核定。
- 完成只由明确“我了解了”或浏览结束动作记录，不通过打开系统权限页、执行终端命令、登录账号计分。中途退出不反复追问。
- 旋转／进程恢复保留当前卡片，导航回来不重放上一次动作。旧页面回调失效，不改变当前运行环境／会话。
- 未就绪、停用、模式不符、权限缺失时说明真实原因：“可先阅读”“前往原有设置”，不显示虚假的已启用／已完成。未知状态不变成成功。
- 打开功能页前保留当前草稿／会话与返回上下文；若原页面有未保存表单或原生确认，先按既有导航约束处理，不抢焦点覆盖。

## 6. 移动端表现

原生优先复用现有主题、导航与DshaDialogBuilder，不引入Compose或另一套UI框架。内容以短列表／卡片页呈现，避免6层嵌套弹窗和只能靠目标控件坐标定位的强制气泡游览。

- Android点击热区至少48dp、相邻动作留足间距；系统状态栏／手势区留白，按钮不被底部导航遮挡。
- 窄屏单栏，底部显式返回／关闭；短屏、大字体、横屏正文可滚动，CTA仍可达。宽屏可列表＋详情，但每个路由仍只有一个owner。
- TalkBack读标题、当前卡片和操作；图标配文字，不只用颜色表示状态。遵循减少动效，不遮挡任务确认或手机控制窗口。
- 这批引导不收集用户输入，所以不自动弹键盘。若后续增加搜索，聚焦不主动抢当前工作台输入；验收键盘避让与返回层级。
- 沿用现有10语言翻译路径，不只硬编码中英文；1.3倍及更大字体、长标签与RTL另测。文案不含示例token、真实路径或命令。

## 7. 实施切片与验收（首包之后）

1. **入口与文案**：按最终集成树核6张卡的来源、导航、离线资源及翻译；功能未接通的入口不展示为可用。
2. **常驻可达＋Web回原生通路**：先验从工作台、直启Web、原生首页、平板设置都能找到指南；仅导航，不能影响任务／终端会话。
3. **首次邀请与阅读状态**：只在合适时机出现一次，可跳过、可重看、升级不重置业务授权；新旧ConfigStore无键冲突。
4. **独立回归与审查**：测试invitation与维护／恢复／确认互斥、拒绝权限、离线、旋转／重建、卸载旧回调、布局／无障碍／十语言。负控：点击每个入口前后，权限／任务开始次数／命令发送／维护提交／备份写入计数均为0（除非用户随后独立明确操作）。
5. **获准设备验收**：新人实测能找到终端、设备授权、备份及故障诊断，不以“6页都点完”代替可用性；未批准设备任务前不自动操作手机。

入库方案不等于实施批准扩大到首包当前生产批次。首包门禁收口后再单独列准确文件范围、版本、自动回归与设备批准；不改变当前overlay修复或正式发行身份。
