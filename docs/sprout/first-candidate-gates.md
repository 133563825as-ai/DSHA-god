# Rebirth：G0／G1命名空间确认与首包门禁清单

> 版本：v0.1 仓库整理版｜日期：2026-11-12，Asia/Shanghai  
> 用途：答复协作方当前两项问题，供合并G0／G1使用；从《DSHA新生计划—协作与接口约定·完整交付稿v0.2》抽取并细化。  
> 状态：包身份为本线已确认；门禁为供双方合并的验收清单，不代表全部已实现、已通过或已授权执行。  
> G0／G1具备讨论和准备输入，不等于G0已经验收，不等于A1自动开工。

## 一、命名空间正式答复

**`dsh.android.client.rebirth`是有意选定，不是笔误。**

Rebirth是DSHA新生计划的隔离实验发行线；包名有意位于DSHA的`dsh.android.client.*`命名空间，不改成`io.github.sunsetrne.dsha.rebirth`。它不是Mod正式发行身份，也不是正式DSHA发布包。

| 项 | 已确认值／边界 |
|---|---|
| applicationId | `dsh.android.client.rebirth` |
| 应用显示名 | `DSHA 新生` |
| 项目／代号 | 新生计划／嫩芽 Sprout |
| 正式DSHA | `dsh.android.client`，身份与数据不动 |
| 参考Mod | `io.github.sunsetrne.dsha`，身份与数据不动 |
| 安装关系 | 可共存，不覆盖正式包或Mod包 |
| 候选签名 | 独立、固定的Rebirth测试证书；不使用正式或Mod发布私钥 |
| 证书状态 | 当前未创建／固定指纹，不能填虚构值；创建后共享公开证书和SHA-256指纹，不共享私钥 |
| 首包versionCode | 保留来源359；以后同线单调递增，不与别线同步 |
| 首包版本标记 | 来源共享版本保留，候选追加`-Rebirth-Sprout.1`；不冒充官方新版本 |
| 跨线数据 | 默认不继承、不自动迁移；导入另核格式、范围、密钥和权限；系统授权不随导入继承 |

当前实现用显式候选构建属性和独立产物核验实现隔离，并未改写原Mod／upstream两套生产身份。协作方可采用独立Rebirth身份文件或其他可验证装配方式，但**不能复用Mod证书假装候选签名，也不能通过放宽原正式证书校验解决构建问题**。具体工程落点可不同，最终包与核验语义必须一致。

主仓库为 https://github.com/DSH-APP/DSHA ，工作／候选仓库为 https://github.com/133563825as-ai/DSHA-god ，参考为 https://github.com/SunsetRNE/DSHA-Sunset-mod 。本轮不修改正式主仓库、不合并main、不配置正式Secrets、不发布Release、不安装设备。

## 二、验收分层与授权分开

| 层 | 验证目标 | 不能代替 |
|---|---|---|
| G1-A 源码与输入 | 精确基线、身份开关、安全及静态门禁 | 实际编译／运行行为 |
| G1-B 自动软件 | 完整单测、Lint、host fast／runtime、software | 真实APK身份和设备行为 |
| G1-C 无签名候选 | 真正release APK及包内身份／资产 | 可安装包、证书或真机验收 |
| G1-D 固定测试签名 | 使用独立候选证书形成可核验安装包 | 获准安装和真机结果 |
| G1-E 设备与覆盖 | 获授权后用同一候选APK验证 | 正式发布资格 |

**当前CI止于无签名候选构建与核验，不持有正式签名密钥。**无签名包必须标`UNSIGNED_NOT_FOR_INSTALLATION`，不能提供给用户当作可安装首包。G0若要求“可安装且共存”，就必须等D／E所需证据，不能用C直接关闭。

本文不是新增签名、私钥创建、上传、安装或发布授权；沿各方既定审批执行，未获准步骤保持未运行。实现、自动测试、包检查、真机分别报告。

## 三、G1-A：源码、输入与静态门禁

| ID | 必须通过 | 失败／反例要求 | 回执 |
|---|---|---|---|
| A01 | 基线锁build359／`92acaa0408cb7b031ee3036c6116c6463ae6b62e`，实现提交完整SHA、分支与工作树清楚 | 不把归档快照提交冒充上游提交；不静默换参考main | 基线、tree、限定diff、干净状态 |
| A02 | 所有输入及工具链按既有锁验证；raw／managed测试runtime绑定同次证明 | 版本、OS／CPU、锁、marker、内容字节不符拒绝；未知输入不接受 | 下载来源、摘要、准备命令、最终字节复核 |
| A03 | 生产身份、正式证书约束、原版权／第三方许可保持 | 非候选构建行为负控；不读生产私钥／用户数据 | 与基线比较及身份测试 |
| A04 | Rebirth候选开关显式、组合合法 | 错误属性、生产签名混入、意外debug／test变体、自动install等应拒绝 | 配置矩阵及实际任务验证；dry-run不冒充编译 |
| A05 | 代码格式、源码卫生、工作流、资源／文档、核心边界门禁 | 不在干净CI用空的“changed files”集合假通过 | 实际检查文件与命令／退出码 |
| A06 | 敏感默认值、caller／任务围栏、退出证明、数据保留等约束不因改名消失 | 不换通道绕拒绝，不按裸PID／端口／名称停止，不自动重放UNKNOWN | 适用安全回归与独立diff审查 |

固定历史输入必须校验真实资产字节；synthetic只用于明示的负控或分支probe，不当历史包／模块。旧代缺席模块必须显式受限，不用新模块填旧包；实际未执行的前驱分支报告0，不以静态负控清单冒充覆盖。

## 四、G1-B：完整软件门禁（顺序、同提交）

| ID | 验证 | 通过条件 |
|---|---|---|
| B01 | 完整host fast | 全部应运行项通过、manifest覆盖无漏项、最终runtime字节复核通过 |
| B02 | 全量Android unit | 真实报告0失败／0错误／无未解释跳过；必需外部fixture实际执行；核用例发现与归属 |
| B03 | Release Lint | 实际完整运行；当前执行线以0错误为必要条件，警告另分类，不说“有警告就等于无问题” |
| B04 | 完整host runtime | 全部适用用例通过，不能用--only／skip集替代完整门禁 |
| B05 | 完整software稳定性阶段 | 由原稳定性脚本真实运行，包含的重复单测／Lint串行执行；不能只看上一层绿 |
| B06 | 候选更新隔离 | 候选不访问正式feed的启动／手动检查、取包下载安装、旧更新任务恢复；普通模式合法正控仍成立 |
| B07 | 修复闭环 | 原失败证据→最小修复→负正控→相关回归→独立完整diff审查，无未处置阻断 |

规则：

1. 同一提交、同一套锁定输入形成完整链，不能拼接不同提交的逐项最新结果凑全绿。
2. 定向测试用于定位／回归，不替代完整阶段；环境失败、崩溃、超时、未知、跳过都不计PASS。
3. 所有会内部启动Gradle的host脚本进入同一串行调度；共享环境同一时刻一个Gradle。独立CI按明确依赖和资源另定。
4. 不以“旧版就失败”豁免。夹具失配、CI准备、生产缺陷及未知分开修；修改范围另核批准。
5. 警告不静默清理，不把全量单测绿推导成所有独立host依赖已准备。
6. 包名开关可能不在默认单测编译路径：默认编译全绿＋注入true的候选行为测试，仍不能替代C层真正候选release编译。

## 五、G1-C：实际无签名候选与资产核验

只有软件门禁完成才进入候选编译。当前已配置的构建入口：

```bash
./gradlew :app:printReleaseIdentity :app:assembleStandardRelease \
  -Pdsha.identity=upstream \
  -Pdsha.unsignedPackage=true \
  -Pdsha.rebirthCandidate=true \
  --no-daemon --max-workers=2
```

该命令是当前Linux候选CI入口，不是安装命令；本机依既有受控Gradle包装器与串行规则运行。协作方不同工程落点应提供等价可复核入口，不直接照抄正式Mod构建命令。

| ID | 实际APK必须证明 |
|---|---|
| C01 | 从真实output metadata定位唯一产物，不猜路径或拿旧包 |
| C02 | 包名`dsh.android.client.rebirth`、所有实际本地化显示名`DSHA 新生`、versionCode359、版本候选后缀正确 |
| C03 | 非debuggable的release；当前首包min30、target37、arm64-v8a；不得改变平台值迁就工具缺项 |
| C04 | Provider authorities及其他身份衍生项在候选命名空间，不冲突正式包；包内校验加获准后的共存实测 |
| C05 | 真正未签名：没有v1签名成员、没有v2／v3签名块；签名工具可用性与“预期未签名失败”分别验证 |
| C06 | 原runtime升级／恢复／managed-assets／第三方许可APK检查均通过；候选测试标志和正式更新隔离证据存在 |
| C07 | 精确源码提交／输入／工具版本绑定，构建未改跟踪源码；产物复制前后SHA一致 |
| C08 | 完整APK SHA-256、字节数、包内badging／manifest、签名检查原始回执和NOT_FOR_INSTALLATION标记 |

“没有正式签名”不等于随意使用临时证书；“apksigner任意失败”也不等于证明未签名，必须排除工具不可用、格式损坏等。

## 六、G1-D：独立固定候选签名（另核授权）

- 不使用Android共享debug证书冒充固定候选发行证书；不使用正式DSHA或Mod私钥。
- 固定证书公开指纹、算法／有效期及签名配置；私钥权限、保管、备份和密码来源可审计，不入Git、不进日志、不共享给协作者。
- 不修改正式身份／原验证器来接受候选；候选独立核验域可复用通用实现，但可信证书与包名上限必须分开。
- 对最终签名APK执行apksigner真实验证，核实际签名方案、证书SHA-256、包名／versionCode及所有资产证明；签名前后内容变化按签名工具语义审计。
- 记录unsigned与signed两个不同SHA及其关系，禁止拿unsigned摘要指代installed APK。
- 签名后的包可以称“可安装候选”，仍不能称“已安装／已验收／正式发布”。

首包尚无签名回执时G0不得填证书指纹或称身份落地全部完成。后续测试证书丢失会破坏同线升级连续性，应保留密钥而非每轮重建。

## 七、G1-E：真机与同线覆盖（另获安装／操作授权）

| ID | 必测场景 | 判定 |
|---|---|---|
| E01 | 共存安装 | 正式／Mod保留原数据和身份，Rebirth私有目录独立；不要求卸载任一旧包 |
| E02 | 初始数据与授权 | 不自动读取／继承正式数据；敏感能力初始关闭；系统授权按候选实际申请 |
| E03 | 启动与容器基线 | 全新／已有环境分别按真实状态走准备／维护，进入容器DSH；旧原生DSH线不因改名重新启用 |
| E04 | 更新隔离 | 候选显示手动更新说明，不访问正式feed或恢复正式下载任务；不因此取消系统安装／维护 |
| E05 | 同Rebirth线覆盖 | 有真实上一候选时用同包同签且更高versionCode覆盖，核配置／数据、runtimeId变化与维护、不拉旧树Web |
| E06 | 失败恢复 | 缺输入、试运行失败、旧会话未确认、空间不足、取消／未知等按阶段失败关闭；原件与现场保留 |
| E07 | 核心冒烟 | 现有页导航／返回、语言／主题、边到边／键盘、桥／终端／屏幕等按首包实际AC核验；敏感业务另有任务授权才执行 |

这是首包基线，不把尚未实施的高刷、Gecko、Root写管理、桌宠等扩展功能塞入首包完成条件；这些需求仍在后续路线，不因此删除。

第一包没有上一Rebirth包时，同线覆盖标“无前代，待下一包演练”，不能使用正式／Mod跨包安装代替覆盖证明，也不伪造上一版。若某项是后续任务的必要依赖，必须补齐或由共同任务范围明确收口，不能仅以N/A关闭依赖。

每份设备回执绑定最终signed APK SHA、设备／系统／WebView、步骤和脱敏证据。不开自动授予权限，不清数据，不借系统设置或UI绕设备策略。
