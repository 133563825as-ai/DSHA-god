## 先读这四件事

1. **目标**：保留Android壳、桥、终端与应急，以容器作为DSH唯一运行底座，渐进建设可组合工作台；不是删除旧代码或全仓翻译重写。
2. **身份**：Rebirth `dsh.android.client.rebirth`／`DSHA 新生`是隔离候选，不覆盖正式DSHA或Mod，不继承其数据与系统授权。
3. **状态**：完整软件门禁未闭合，尚无嫩芽APK；文档、源码、自动测试、包检查和真机证据分开。
4. **协作**：从精确共同分支起任务分支、独立审查后提PR；CI不代替人工审查，也不自动获得签名／安装／发布授权。

## 新同事怎么开始

```bash
git clone https://github.com/133563825as-ai/DSHA-god.git
cd DSHA-god
git switch integration/sprout
git switch -c fix/你的任务名
```

开工前先读[根开发约束](../../AGENTS.md)和本专区。任务记录来源完整SHA、文件范围、owner、验收、负正控与回退；并行写入分离路径，同一共享环境Gradle串行。不要直接覆盖其他人的活跃分支，不把ZIP整包覆盖当合并。

默认分支只是协作入口。候选CI目前只监听特定功能分支，其他PR可能仅跑部分旧工作流；共同分支／PR完整门禁需另做受控接线，不能看到一个绿勾就声称首包全验收。

## 文档维护与版本管理

- **唯一动态状态入口**：[版本台账](baseline-and-validation.md)。其他页面写标准与边界，不复制易过期计数。
- 结论包含时点、完整源码SHA、输入／产物身份、CI链接、命令和证据范围。定向通过不拼成完整全绿。
- 已确认决策、共同提案、未实现、已实现未验、已验分开。收到附件中的Accepted不自动成为本线批准。
- 已发布文档的旧结论不悄悄覆写：修订时更新[修订记录](CHANGELOG.md)，写取代关系与原因。协议字段不兼容变更需显式新版本与适配说明。
- 不把凭据、私钥、原始用户备份、私有路径／设备标识、含敏感信息的诊断或大二进制输入放入Git。公开说明优先用合成样例与脱敏摘要。
- 产品版本、Git提交、文档版本、协议schema、运行时身份互不替代。tag不是Android可降级或数据可回退的证明。
- 本批只推文档分支，不自动合共同分支、不动main，不配置保护规则或Secrets。合并与后续维护动作按明确批准执行。
